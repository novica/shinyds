# Updating shinyds when Designsystemet changes

When a new Designsystemet version is released there are two paths:

- **Automated** — the GitHub Action `.github/workflows/update-components.yml` does
  everything and opens a PR. Trigger it from the Actions tab with the new version number.
- **Manual** — follow the steps below when you need more control or are working locally.

Current bundled version: **1.14.0**

---

## Manual update procedure

### 1. Build the upstream

```bash
cd ../designsystemet
git fetch --tags
git checkout @digdir/designsystemet-css@<new-version>
pnpm install --frozen-lockfile
pnpm build
```

### 2. Copy assets

```bash
# From the shinyds package root:

cp ../designsystemet/packages/css/dist/src/index.css \ 
   inst/www/css/designsystemet.min.css

cp ../designsystemet/packages/web/dist/umd/index.js \
   inst/www/js/designsystemet-web.umd.js
```

The JS bundle **must be the UMD build** (`dist/umd/index.js`), not the ESM build.
ESM bare specifiers don't work in browsers without a bundler.

### 3. Check for new web components

```bash
Rscript tools/bootstrap-registry.R
```

This compares `custom-elements.json` against `tools/component-registry.yaml` and
prints any tags that are new or removed. If new components appear, review the
printed YAML skeletons, fill in `binding:` and any known attributes, then either
paste them into the registry manually or re-run with `--write` to append them
automatically.

### 4. Regenerate R wrappers and JS bindings

```bash
Rscript tools/generate.R --clean
```

This removes all previously generated R files (those with the
`# Generated by tools/generate.R` header) and writes fresh ones from the
updated registry. Hand-written files (no header) are never touched.

Components marked `custom_structure: true` in the registry are skipped by the
generator — review and update their hand-written wrappers manually if the
upstream API changed.

### 5. Bump version strings

In **`DESCRIPTION`**, update `Version:`.

In **`R/ds-dependencies.R`**, update both `version = "..."` strings in the
`htmlDependency()` calls to match the new Designsystemet version.

### 6. Run checks

```r
devtools::document()
devtools::test()
NOT_CRAN=true devtools::test()   # includes shinytest2 browser tests
devtools::check()
```

### 7. Test the example apps

```r
shiny::runApp(system.file("examples/basic",    package = "shinyds"))
shiny::runApp(system.file("examples/faithful", package = "shinyds"))
shiny::runApp(system.file("examples/showcase", package = "shinyds"))
```

Verify components render correctly and Shiny inputs report values.

---

## Tools reference

| Script | Purpose |
|---|---|
| `tools/bootstrap-registry.R` | Diff upstream tag names vs. registry; scaffold YAML for new components |
| `tools/generate.R --summary` | Print all components and their binding types |
| `tools/generate.R --dry-run` | Preview what would be generated without writing files |
| `tools/generate.R --clean` | Regenerate all generated R files and JS bindings |
| `tools/generate.R --component NAME` | Regenerate a single component |

## File locations

| What | Where |
|---|---|
| CSS asset | `inst/www/css/designsystemet.min.css` |
| JS (UMD) asset | `inst/www/js/designsystemet-web.umd.js` |
| Shiny bindings | `inst/www/js/ds-bindings.js` |
| Component registry | `tools/component-registry.yaml` |
| Generated R files | `R/` (header: `# Generated by tools/generate.R`) |
| Hand-written R files | `R/` (no generated header) |

## Troubleshooting

**Components not styled** — check that `inst/www/css/designsystemet.min.css` was
copied and that `ds_dependencies()` path is correct.

**Web components not working** — ensure the UMD bundle was used, not the ESM build.
Check the browser console for JS errors. Verify `ds-shiny-input` class is on the
element.

**Phantom input errors (`:ds:*`)** — the JS guard in `ds-bindings.js` and the
`zzz.R` handler suppress these. If a new component triggers them, see the
"Behaviour-only modules" section in `CLAUDE.md`.

**Shiny inputs returning NULL** — verify the JS binding's `find()` selector
matches the element's classes, and that `getId()` is defined.
